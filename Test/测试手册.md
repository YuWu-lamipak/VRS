## 🚀 快速开始

### 前置条件

确保以下服务正在运行：

```cmd
# 检查服务状态
netstat -ano | findstr "8066 8601 3306 6379"
```

| 服务 | 端口 | 启动脚本 |
|------|------|----------|
| lemei-admin | 8066 | `start-backend-fixed.bat` |
| lemei-api | 8601 | `start-api.bat` |
| MySQL | 3306 | 自动启动 |
| Redis | 6379 | 自动启动 |

### 测试覆盖

#### lemei-system（6个单元测试）

**测试类**: `LmCarApplicationServiceTest`

测试方法：
1. `testSelectCarNumberByApplicationId` - 根据预约ID查询车牌号
2. `testCheckEnterStatusInfoExists_WhenExists` - 检查车辆进厂状态（存在）
3. `testCheckEnterStatusInfoExists_WhenNotExists` - 检查车辆进厂状态（不存在）
4. `testCheckScrapAdvanceInfoExists` - 检查废料预付款信息
5. `testInsertLmCarApplication` - 插入车辆预约记录
6. `testUpdateLmCarApplication` - 更新车辆预约记录

**测试内容**：
- 车辆预约服务核心业务逻辑
- 数据查询和处理功能
- 业务规则验证
- 使用Mockito模拟数据层

---

#### lemei-api（7个集成测试）

**测试类**: `CarApplicationApiTest`

测试接口：
1. `testProCard_Success` - 制卡接口（成功场景）
2. `testProCard_NotReserved` - 制卡接口（未预约场景）
3. `testGuardStatistics` - 门卫首页数据统计
4. `testGetReasonList` - 获取申请原因列表
5. `testGetScrapList` - 获取废料列表
6. `testGetSupplierList` - 获取供应商列表
7. `testGetDetail_InvalidId` - 获取预约详情（无效ID）

**测试内容**：
- REST API接口功能测试
- 使用REST Assured进行HTTP请求测试
- 验证响应状态码和数据格式
- 测试正常场景和异常场景

**注意**：这些是外部API接口测试，不是管理后台接口。

**测试类**: `LmCarApplicationControllerTest`

测试方法：
1. `testEnterOrOut_WhenCarAlreadyEntered` - 进出厂操作（车辆已进厂）

**测试内容**：

**管理后台功能说明**：

Admin模块包含30+个管理接口，但目前只有2个单元测试。主要功能包括：

**查询功能**：
- `/system/application/list` - 查询车辆预约列表（支持权限过滤）

- `/system/application/{applicationId}` - 获取预约详情
- `/system/application/saleList` - 查询销售列表
- `/system/application/saleInfo/{lmId}` - 查询销售详情
- `/system/application/statis` - 数据统计
- `/system/application/getSupplierList` - 查询供应商
- `/system/application/getGlobalVariable` - 查询全局变量

**新增/修改功能**：
- `POST /system/application` - 新增车辆预约记录
- `PUT /system/application` - 修改车辆预约记录
- `PUT /system/application/statusEdit` - 修改状态
- `PUT /system/application/loseWeightEdit` - 修改扣重

- `PUT /system/application/scrapAppointmentWeightEdit` - 修改废料预约重量

**删除功能**：

**导出功能**：

**集成功能**：

## 🚛 称重流程测试

### 智能版（推荐）⭐⭐⭐⭐⭐

**脚本**: `test-weighing-flow-auto.bat`

**特点**：
- ✅ 自动生成唯一测试数据（车牌号、卡片ID）
- ✅ 自动更新预约记录（**预约日期自动设置为今日**）
- ✅ 执行完整测试流程
- ✅ 自动恢复原始数据（**预约日期保持为今日**）
- ✅ 可无限次重复运行
- ✅ **无需担心日期问题**：脚本会自动将预约日期设置为当天

**重要说明**：
- 制卡接口要求预约日期必须是今日，否则会失败
- 智能版脚本会自动处理日期问题，确保测试始终使用当天日期
- 即使隔天运行，脚本也会自动更新预约日期为当天

**使用方法**：

```cmd
# 双击运行或命令行执行
.\test-weighing-flow-auto.bat
```

**测试流程**：

1. ✅ 创建/更新预约记录
2. ✅ 制卡
3. ✅ 待上一磅
4. ✅ 一磅写入
5. ⚠️ SAP导入DN数据（危废业务可跳过）
6. ✅ 待上二磅
7. ✅ 二磅写入
8. ✅ 退卡
9. ✅ 恢复测试数据

**测试报告**：`TestReport/WeighingFlow_Auto_[UniqueID].txt`

```sql
    goodsWeight = NULL,

    truckWeight = NULL,

```

## 🔧 故障排除

### 常见问题

#### 1. 服务未运行

**症状**：测试失败，提示连接错误

**解决方案**：

```cmd
# 检查服务状态
netstat -ano | findstr "8066 8601"

# 启动服务
start-backend-fixed.bat
start-api.bat

# 等待15秒让服务完全启动
```

#### 2. 数据库连接失败

**症状**：测试失败，提示数据库连接错误

**解决方案**：

```cmd
# 检查MySQL服务
netstat -ano | findstr "3306"

# 检查数据库配置
# 文件：VRS/lemei/lemei-api/src/main/resources/application-dev.yml
# 确认：url、username、password配置正确且缩进正确（8空格）
```

#### 3. 测试报告乱码

**症状**：测试报告中文显示为乱码

**解决方案**：

测试报告已使用UTF-8编码生成，如果仍有乱码：

```cmd
# 使用支持UTF-8的编辑器打开
# 推荐：VS Code、Notepad++、Sublime Text
```

#### 4. 称重流程测试失败

**症状**：智能版测试某个步骤失败

**解决方案**：

```cmd
# 1. 查看详细错误信息
type TestReport\WeighingFlow_Auto_[最新文件].txt

# 2. 检查API服务日志
# 查看API服务窗口的错误信息

# 3. 验证数据库数据
mysql -h localhost -P 3306 -u root -proot123 -D carbooking -e "SELECT * FROM lm_car_application WHERE application_id='ee9c31488b1f45be908e01ca7c61bc21';"
```

#### 5. 端口被占用

**症状**：服务启动失败，提示端口已被占用

**解决方案**：

```cmd
# 查找占用端口的进程
netstat -ano | findstr "8066"
netstat -ano | findstr "8601"

# 停止进程（替换<PID>为实际进程ID）
taskkill /F /PID <PID>

# 重新启动服务
start-backend-fixed.bat
start-api.bat
```
