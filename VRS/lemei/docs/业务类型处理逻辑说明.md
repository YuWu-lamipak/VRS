# 业务类型处理逻辑说明

## 业务类型定义

系统支持5种业务类型：
- **0 = 采购**
- **1 = 销售** 
- **2 = 废料**
- **3 = 其他**
- **4 = 固废危废处置**

## 各业务类型处理逻辑

### 业务类型0：采购
- **容差控制**: 可选是否启用控制，默认启用容差控制
- **容差参考值**: 从全局变量表 `lm_global_variable` 获取 (`soToleranceAdd`, `soToleranceDec`)
- **预约重量**: 基于实际预约重量
- **审核逻辑**: 使用系统配置的容差计算浮动重量

### 业务类型1：销售
- **容差控制**: 默认启用容差控制
- **容差参考值**: 从全局变量表 `lm_global_variable` 获取 (`soToleranceAdd`, `soToleranceDec`)
- **预约重量**: 从SAP接口获取
- **审核逻辑**: 审核时设置预约重量为0，但使用系统配置的容差

### 业务类型2：废料
- **容差控制**: 目前默认不启用容差控制
- **预约重量**: 从SAP接口获取
- **管控要求**: 预约重量不为0
- **审核逻辑**: 
  - 审核时设置预约重量为0
  - 需要检查OA预付款审批信息
  - 容差设为0

### 业务类型3：其他
- **容差控制**: 不管控
- **审核逻辑**: 容差设为0，基于实际预约重量计算浮动重量

### 业务类型4：固废危废处置
- **容差控制**: 目前不启用容差控制
- **审核逻辑**: 
  - 审核时设置预约重量、上浮重量、下浮重量都为0
  - 容差设为0

## 关键配置

### 全局容差配置
- **表**: `lm_global_variable`
- **字段**: 
  - `soToleranceAdd`: 正容差
  - `soToleranceDec`: 负容差

### 预约记录字段
- **表**: `lm_car_application`
- **关键字段**:
  - `businessType`: 业务类型
  - `enableControl`: 启用管控 (0=否, 1=是)
  - `appointmentWeight`: 预约重量
  - `toleranceAdd`: 正容差
  - `toleranceDec`: 负容差
  - `upFloatingWeight`: 上浮重量
  - `downFloatingWeight`: 下浮重量

## 代码位置

### 审核逻辑
- **文件**: `VRS/lemei/lemei-admin/src/main/java/com/lemei/adminweb/system/LmCarApplicationController.java`
- **方法**: `authen()`

### 重量更新逻辑
- **文件**: `VRS/lemei/lemei-api/src/main/java/com/lemei/service/impl/ApplicationServiceImpl.java`
- **方法**: `updateApplicationWeight()`

### 容差配置获取
- **文件**: `VRS/lemei/lemei-api/src/main/java/com/lemei/mapper/CarApplicationMapper.java`
- **方法**: `getTolerance()`
- **SQL**: `select soToleranceAdd as toleranceAdd,soToleranceDec as toleranceDec from lm_global_variable`

## 注意事项

1. **废料业务特殊性**: 虽然目前不启用容差控制，但有预付款审批要求
2. **销售业务**: 预约重量从SAP获取，但审核时会被设为0
3. **固废危废处置**: 完全不进行重量管控
4. **容差计算**: 浮动重量 = 预约重量 × (1 + 容差率)

## 未来扩展

根据业务需求，可能需要：

2. 为固废危废处置业务增加特殊管控逻辑
3. 优化容差配置的灵活性（按业务类型配置不同容差）
